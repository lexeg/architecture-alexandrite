# Анализ

### Логирование информационных сообщений
1. онлайн-магазин:
    - пользователь создал новый заказ (время, id пользователя, номер заказа).
    - пользователь загрузил файл с 3D-моделью (время, id пользователя, название файла).
2. CRM:
    - заказ подтверждён (время, id заказа).
    - заказ завершён (время, id заказа).
3. MES:
   - оператор взял заказ в работу (время, id оператора, id заказа).
   - оператор выполнил заказ (время, id оператора, id заказа).
   - оператор начал упаковывать заказ (время, id оператора, id заказа).
   - заказ отправлен покупателю (время, id оператора, id заказа).

### Другие типы информационных сообщений
1. Error: непредвиденные исключения, возникшие при выполнении кода; ошибки при работе с очередью или БД.
2. Warn: ошибки в запросах (400); возможно, ошибки при отсутствии запрашиваемой информации (404).
3. Debug: только при отладке приложения детализированное логирование работы приложения.

# Мотивация

Логи помогают собирать и анализировать данные о работе системы. Это помогает обнаружить ошибки.\
Также, логи — это один из источников информации для мониторинга.
Если внедрить логирование, то это позволит компенсировать ограничения мониторинга и получить более полную картину.\
Например, система мониторинга прислала алёрт. Можно сразу посмотреть ошибки из логов. И быстрее установить причину проблемы.\
Причины:
- Более быстрое решение проблем и повышение надёжности системы
- Ценные бизнес-инсайты
- Повышение удовлетворённости пользователей

### Логирование критичных компонентов системы
В первую очередь стоило бы внедрить логирование и трассировку в Shop API, потому что на данный сервис ложится ответственность за работу с заказами (CRUD-операции).
Затем приступить к логированию MES API, потому что от него зависят вычисления и расчеты по будущему изделию.

### Политика безопасности в отношении логов
- доступ к логам будет по логину и паролю. Доступ будут иметь: разработчики, тестировщики.
- чувствительные данные не должны храниться в логах. Либо, с помощью регулярных выражений предварительно маскироваться, например: "username = ivanov; password = ********".

### Политика хранения в отношении логов
- будет создаваться отдельный индекс для логов за каждый день.
- с помощью ILM будет настраиваться срок жизни индекса (30 дней) и размер.

# Мероприятия для превращения системы сбора логов в систему анализа логов
Так как команда небольшая либо на начально этапе текущими силами алертинг не будет настраиваться и будет запланирован в дальнейшем.
Либо потребуется нанять еще 1-2 DevOps специалистов для усовершенствования работы с системами мониторинга и логирования.\
В дальнейшем понадобится алертинг для быстрого реагирования на "взрыв" 500ок и не только с оповещением участников команды (например, службы дежурных инженеров)
