# Анализ

Лучше всего добавить кеширование для сервисов, управляющих заказами (Shop API) и MES API

# Мотивация

Причины следующие:
- Долгое исполнение запросов. Это отрицательно влияет на пользовательский опыт.
- Уменьшение нагрузки на сервисы и базы данных.

Кеширование будет внедряться в Shop API и MES API.

# Предлагаемое решение

### Выбор кеширования

Планируется применить клиентское и серверное кеширование.\
Клиентское кеширование - так как процесс изготовления не быстрый, то нет смысла запрашивать новые данные каждый час-два из БД.
Можно для каждого клиента применить клиентское кеширование со временем обновления раз в сутки. В течение суток запрашиваемые заказы клиент будет видеть из кеша.
Спустя сутки кеш сбрасывается.\
Серверное кеширование - можно попробовать применить в двух кейсах:
- кешировать справочные таблицы, необходимые при создания заказа. Справочные таблицы меняются редко. Можно при запуске сервиса "прогреть" кеш и положить справочные данные.
Если произойдет изменение в данных таблицах, то можно будет обновить в кеше информацию. Можно применить Cache-Aside или Read-Through.
Остальные паттерны в данном случае избыточны, потому что не требуется прямой работы кэша с БД или первичной записи в кэш информации и только затем в БД.
- кеширование информации о новых заказах. В будущем, после настройки системы мониторинга, можно попробовать применить Refresh-ahead кеширование новых заказов.
Для операторов можно создать страницу, отображающую информацию о новых заказах, где применить данный вид кеширования.
Не нужно будет каждый раз запрашивать из БД информацию о новых заказах. А если новый заказ появится, то он тут же попадет в кеш и в БД.
Данный паттерн подойдет лучше всего, потому что при получении информации о новых заказах превалируют операции чтения и позволяет оперативно передавать информацию о новых заказах, от количествах которых зависит выручка операторов.

### Стратегия инвалидации кеша

1. Временная инвалидация
- Самый простой способ. Устанавливается фиксированное время жизни данных в кеше.
- Позволяет хранить на стороне пользователя закешированные данные о заказах. Данные будут обновлены браузером черех указанное время.

2. Инвалидация на основе изменений
- Кеш инвалидируется каждый раз, когда происходят изменения в данных в БД.
- Если в справочных таблицах произойдут изменения (редко), то кеш будет инвалидирован и получит актуальные данные.
