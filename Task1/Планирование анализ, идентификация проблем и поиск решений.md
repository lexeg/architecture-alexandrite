# Анализ

  - С ростом количества заказов и увеличения обращений к системе появились жалобы клиентов менеджерам по продажам.
  - После открытия API заказаов стало больше, но увеличилось и число жалоб от клиентов на просроченные заказы.
  - Жалобы со стороны пользователей API. Представители компаний ежедневно сообщают, что не получили свои заказы.
  - Жалобы от операторов при работе со страницей MES. Система долго прогружается.
  - Компания потеряла несколько крупных контрактов.
  - В системе развернут только один экземпляр каждого типа приложения.
  - В системе также только по одному инстансу БД для приложений системы.
  - Нет автотестов.
  - CRM API ходит напрямую в БД интернет-магазина (нарушение Database per service).
  - Информация о заказах лежит разрозненно (заказы покупателей и продавцом ювелирных изделий в Shop DB, заказы пользователей API в MES DB).

# Поиск решения

- Вероятно, заказы от клиентов не поступают в общую очередь сообщений и операторы о них ничего не знают.
- Нужно настроить централизованное получение заказов из разных источников.
- Исключить прямой доступ к БД интернет-магазина другим сервисам и API (CRM API). Все обращения через Shop API.
- Настроить репликацию баз данных.
- Поднять дополнительные инстансы приложений.
- Написать автотесты на самые критичные сценарии, которые могут привести к багам уровня high/highest, чтобы при деплое на dev, как можно раньше узнавать о проблемах.
- Создать для операторов страницу, которая будет отображать новые заказы.
- Настроить мониторинг системы.
- Добавить трейсинг.
- Улучшить логирование и анализ логов.
- Проанализировать запросы к системе и запрашиваемые данные, чтобы внедрить кеширование, для ускорения получения данных пользователями.
- Подумать, как вернуть доверие клиентов и компаний, контракты с кем сорвались (акции, скидки на контракты и тд).

# Расстановка приоритетов

1. Настроить централизованное получение заказов из разных источников, чтобы устранить проблему потерянных заказов.
2. Исключить прямой доступ к БД интернет-магазина другим сервисам и API (CRM API). Все обращения через Shop API. 
3. Написать автотесты на самые критичные сценарии. Чтобы на ранних этапах разработки узнавать о проблемах.
4. Добавить трейсинг. 
5. Добавить логирование в сервисы системы. 
6. Настроить репликацию баз данных и поднять дополнительные инстансы приложений. Чтобы система смогла выдерживать нагрузку.
7. Добавить кеширование часто запрашиваемых данных.

### Планы по изменению архитектуры в ближайшие полгода

- Необходимо избавиться от проблем с "потерянными" заказами, т.к. это потеря выручки, доверия клиентов и невозможность отслеживать объемы работ. Для этого потребуется внести изменения в процессы взаимодействия сервисов друг с другом.
- Нужно начать развертывание и постепенное внедрение систем мониторинга, логирования, трейсинга в систему. Это позволит увидеть нагрузку на компоненты системы (какие более загружены, какие меньше). Выявлять узкие места. Планировать горизонтальное масштабирование.
- Добавить инстансы приложений и репликацию БД, чтобы повысить отказоустойчивость.
